# 硬币检测与缺陷分级系统（Python + OpenCV）

> 测控专业个人项目 · 以硬币为对象，模拟工业零件视觉质检全流程
> 技术栈：Python · OpenCV · NumPy · openpyxl

## 项目简介

用 OpenCV 传统图像处理实现对硬币的自动化检测：测量真实直径 → 判定圆度与尺寸 → 按偏差分级
（合格 / 轻度 / 中度 / 重度）→ 输出可视化结果图与 CSV/Excel 报表。

完整模拟工业视觉链路：**采集 → 预处理 → 特征提取 → 像素标定 → 判定分级 → 报表输出**。

## 功能特性

- 双模式：批量图片检测 / 摄像头实时检测
- 声明制检测：指定面额，按对应国标尺寸判定
- 像素 → 毫米标定换算
- 四级缺陷分级 + 分级配色可视化（绿/黄/橙/红）
- 批量导出 CSV / Excel 检测报表
- **结果可追溯**：结果图与报表保留原图文件名，未检出目标也单独成行，可逐条回查

## 处理流程

```
读图 → 灰度 → 高斯模糊 → Canny 边缘 → 轮廓筛选 → 特征计算(面积/周长/圆度/直径)
    → 像素→毫米(标定) → 按声明面额判定(圆度+尺寸超差) → 四级分级 → 可视化 + 报表
```

## 快速开始

```bash
pip install -r requirements.txt
cd coin_detect

# 批量模式：检测指定文件夹内图片并导出报表（结果默认输出到 <input>/result）
python main.py --mode batch --coin 1元 --input <图片文件夹>

# 实时模式：摄像头逐帧检测，按 q 退出
python main.py --mode camera --coin 1元
```


| 参数 | 说明 | 可选值 |
| :--- | :--- | :--- |
| `--mode` | 运行模式 | `batch`（默认）/ `camera` |
| `--coin` | 被检面额（必填） | `1元` / `5角` / `1角` |
| `--input` / `-i` | 批量模式：待检测图片文件夹（batch 必填） | 任意路径 |
| `--output` / `-o` | 结果输出文件夹（选填，默认 `<input>/result`） | 任意路径 |

| 序号 | 图片名称 | 面额 | 直径(mm) | 圆度 | 偏差(mm) | 方向 | 严重程度 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |

- 某张图未检出任何目标时，仍输出一行「未检出」，不会从报表中消失

## 判定逻辑

1. **圆度**：`面积 / 外接圆面积`（理想圆实测 ≈0.99），低于 `min_circularity` 判形状不合格
   - 刻意不用教科书式 `4πA/P²`：数字轮廓的周长被阶梯效应撑高约 5%，**数学上完美的圆也只能拿 0.899**，
     门槛 0.9 按构造跨不过去 —— 结果是任何硬币一律判「不合格」，分级永远走不到
   - 两者数学同源（把 `P` 换成 `2πr` 即得 `A/πr²`），只是这个版本对锯齿免疫
2. **尺寸**：直径取 `√(4·面积/π)`（面积等效直径），**不取外接圆直径**
   - 外接圆对缺料不敏感：刀口啃掉一块，外接圆仍是原来那个圆 —— 而本工具要检的正是缺口
   - Canny 环的外多边形比真实边缘恒定外扩约 1.2px（本标定下 +0.12mm），一项就吃光 0.1mm 预算
3. **两路独立判据**，各管各的事，取**更差的一档**作总评：

   | 路 | 量 | 分档依据 | 抓什么 |
   | :--- | :--- | :--- | :--- |
   | 尺寸 | 超出量 = abs(实测直径 − 标称) − 允差 | ≤0 合格；≤0.3 轻度；≤0.6 中度；否则重度 | 整体偏大 / 偏小 |
   | 缺损 | 径向最大凹陷（轮廓点到圆心的最小距离，相对中位半径） | ≤0.4 合格；≤0.8 轻度；≤1.5 中度；否则重度 | 刀口、缺口、崩边 |

   为什么必须两路：实测 **1mm 深的缺口只让等效直径变小 0.035mm**（面积是全局量，局部缺料
   摊到整圆就没了），只有允差的 1/7 —— 只看直径必然放过；而径向凹陷如实报出 1.001mm。
   反过来整体磨小时凹陷恒为 ~0.10mm（噪声底），不会误报成刀口。两条路互不污染。

   `判定依据` 列会写明这一档是谁给的（`尺寸偏大` / `刀口1.00mm` / 同档时两者并列）。

> 尺寸档用「超出量」而非「绝对偏差」，使不同面额共用同一套分级标准。

## 测量链自检（不依赖相机）

```bash
python tools/selftest_measure.py --coin 1元
```

画一批**直径和缺口深度都已知**的图形，走完全相同的管线，把「像素→毫米→分级」这条链单独量出来。
真硬币的直径未知，只能看出重复性看不出准确度；这一步的作用是：**只要这里报错，问题就一定在代码里**，
跟拍摄无关。

当前实测（2026-10-10，ppm=8.6510）：直径链最大误差 **0.011mm**（1元）/ **0.021mm**（1角），
阈值 0.05mm；缺口深度 0.5/1.0/2.0/3.0mm 测得 0.453/0.992/1.781/2.539mm，四档分级全部触发。

> **深缺口那两档系统性低估是已知性质，不是 bug。** 质心会被啃掉的材料推向缺口反向，
> 缺口越深低估越多（3mm 报 2.539 = −15%）。所以自检判据写成「**落对分档 + 相对偏差 <25%**」，
> 而不是「绝对误差 <0.15mm」—— 旧判据用后者，于是每次跑都常态性 FAIL 两行，
> 而自检的全部意义是「它报错就一定是代码问题」。**误报常态化的自检，会把人训练成不看它的输出。**
> （这与 `edge_check_mm` 从 0.3 改 1.2 同因：门限的下界是探测器自身的分辨率。）

工具本身带退出码（直径误差、分档、四档覆盖任一不合格即 exit 1），可直接进 CI。

## 检测参数

| 参数 | 值 | 说明 |
| :--- | :--- | :--- |
| `ppm` | 8.6510 | 每毫米像素数（2026-10-10 用 A4 纸重标定，1px = 115.6µm；装置动过必须重标） |
| `calib_image_size` | 3072×4096 | 标定图尺寸，待测图必须同尺寸，否则 ppm 不适用 |
| `calib_center` | (1536.9, 1421.1) | **标定纸心，ppm 只在这里严格成立。它不等于画面中心**（本装置偏上 72mm） |
| `diameter_gate_mm` | 2.0 | 尺寸闸门：离标称超过 2mm 的轮廓不是币，是背景。闸门在流水线里，不只在校验工具里 |
| `min_circularity` | 0.9 | 形状合格阈值。⚠ 采信币里实测最小 0.841（直径读数正常），**这个值会误杀良品，待降到 0.80** |
| `edge_check_mm` | 1.2 | 双路互检：多边形读数与径向读数之差超过它标「轮廓可疑」。**下界是探测器自身分辨率** —— 旧值 0.3 低于干净币上的实测分叉 0.56，把好币 6/6 标成可疑 |
| `coin_spread_max_mm` | 0.05 | 枚级拒收：同枚重拍的组内极差上限 |
| `coin_nominal_max_mm` | 0.5 | 枚级拒收：枚均值离标称上限。**组内一致 ≠ 读数正确**，只有这条外部锚能拦整枚读错的样本 |
| `grade_light` / `grade_mid` | 0.3 / 0.6 | 尺寸档刀口（超出量，毫米） |
| `defect_light` / `defect_mid` / `defect_heavy` | 0.4 / 0.8 / 1.5 | 缺损档刀口（径向凹陷，毫米）；0.4 = 4 倍噪声底，**已被真样本验证够用**（采信币实测最大 0.22mm） |

| 面额 | 标称直径 | 允差 |
| :--- | :--- | :--- |
| 1元 | 22.25mm（2019 版） | ±0.25 |
| 5角 | 20.5mm | ±0.25 |
| 1角 | 19.0mm | ±0.25 |

> **1元 必须认版别。** 1999~2018 版（兰花 1元）是 **25.00mm**，2019 版（大数字 1，现行流通）
> 是 **22.25mm**，两版都在流通。本项目样本是 2019 版。混批会有一半被判超差。

> **允差 ±0.25mm 不是国标。** 查不到可引用的造币直径公差，就没有编一个数字。
> 它是按本测量系统自身能力定的「最小可判带宽」：比例尺梯度 ±0.093 + 测量链 0.014 + 像素噪声 0.10
> 合成约 0.14mm，取 0.25 留了余量。旧值 ±1.25（直径的 5%）比整个精度预算大 12.5 倍，
> 会把一切判成合格、分级形同虚设。
>
> ⚠ **但 ±0.25 现在还不能用来判合格。** 卡尺证明这 10 枚 1元 彼此相差不超过 0.1mm，
> 而相机在采信枚上给出 22.026~22.249（**枚间极差 0.223mm**）。也就是说**枚间散布里大部分
> 是相机自己的系统偏差**，与允差带宽同量级 —— 拿它判 0.25 会把好币判成超差。
> 重复性（组内 0.004mm）是真的，**准确度还差一步**。
> SPC 控制限仍不出：采信枚 7 < 8（重拍的张数不能顶枚数，同一枚的固定偏差不会随重拍平均掉）。

## 已知局限

- **报的是「光学轮廓直径」，不是卡尺直径。** 硬币边部有倒角和齿，视觉抓的是梯度峰值所在位置，
  与卡尺两量爪接触的"平坦带"不是同一个定义，两者之间存在系统性差异。这是测量原理决定的，
  换更贵的相机也不会消失 —— 只能靠写清定义、或用卡尺建立映射来消除。
- **缺损门限已用真样本验证，不必再抬。** 之前担心真币齿边会把径向凹陷底噪从合成的 0.097mm
  顶上去、从而需要重定 `defect_light = 0.4`。实测采信币：1元 最大 **0.22mm**、5角 0.20、
  1角 0.26 —— 全部在 0.4 之下且留有余量，**门限够用**。
  （原先报表里那个"1元 缺损 max 2.44mm"不是底噪，是读错的样本闭到错结构上算出的假缺损。
  现已改为只统计采信枚。）
- **画面比例尺不是常数**（标定图对边差 0.74%）→ 待测物必须放在**标定纸心**附近。
  纸心是 `calib_center`，本装置它在画面中心**上方 72mm**，所以"对准镜头正下方/画面中心"
  反而会偏出窗口。用 `python tools/check_placement.py <试拍图>` 量出偏了多少毫米并给出挪动方向。
  偏离 72mm 的后果：重复性和线性度基本不受影响（那是恒定偏置，做差时共模抵消），
  只有"相对标称"那一列会带上约 0.06mm 偏移。真正要紧的是**每次都放同一个位置**。
- **本装置的胶带记号比标定纸心低 2.0mm（实测，不是手抖）。** 53 张检出帧的币心相对
  `calib_center`：dx 中位 +1.0px（散布 −4~+12，随机），**dy 中位 +17.0px（散布 +1~+33，
  全部同向）**。手抖会两边散，单向就是固定偏差。所以 `check_placement` 报的"偏离纸心 2.1mm"
  基本不是操作问题。对直径影响 0.003mm 可忽略，但**别再把它当手抖去"纠正"**。
- **准确度已用卡尺核对，结论是可用但不够判公差。** 卡尺（±0.1mm）测 10 枚 1元 均值 22.28，
  相机在采信枚上均值 22.162 ⇒ **−0.12mm**，与卡尺自身不确定度同量级。
  之前那句"相机偏小 0.23mm"**是被错样本污染出来的**，已作废。
  线性度两步 PASS（1角→5角 残差 +0.094mm，5角→1元 +0.050mm）。
- **⚠ 已知缺陷：约 3/10 的 1元 拍不出可信读数。** 表现为整枚读小 1mm、或同组内在两道边之间
  跳变、或整组检不出。六个机制假设（样本特殊 / Otsu 区域分割 / Canny 高门限 / 币缘反差 /
  币被亮区盖住 / 碎弧圆拟合）**全部被测量否掉，机制未解**。
  当前处置是**拒收而非修复**：`coin_spread_max_mm` + `coin_nominal_max_mm` 两条外部锚能把
  它们全部拦下（本批与卡尺真值零冲突），代价是这批样本只有 7/10 可用。
  关键教训：**组内一致 ≠ 读数正确** —— 读错的那枚组内极差只有 0.008mm，它只是稳定地闭在
  同一道错边上。任何只看组内散布的门禁都拦不住它。
- 声明制需运行前指定面额；若放错币种，会判为「尺寸严重超差」而非主动防错
